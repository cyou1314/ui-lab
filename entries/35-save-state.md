# 保存状态（保存中 / 已保存 / 保存失败 / 草稿未同步）

- 段位：第 9 段 状态与边角（保存状态）
- 状态：待试（trial）
- 一句话结论：保存状态要一直挂在用户看得见的地方、但绝不抢戏——打字就变「正在保存…」，存好只留一句「已保存 · 时间」，失败只说清哪一步没存上、点「重试」只重发失败那条，离线时草稿照写、联网后自己补发。
- 效果图：[assets/save-state.png](../assets/save-state.png)
- 拆解数值：
  - 位置（锁死）：编辑器顶栏右端、标题旁边常驻一格，不许放进菜单里、不许只在保存瞬间闪现；字号 12px、次级灰 #5B6572（建议）；成功态的小勾用降饱和绿 ≈#2F9E6E（建议，与条目 33 同色），失败态用降饱和红 ≈#D64545（建议）
  - 四态：① 已保存——「已保存 · HH:MM」，时间是最后一次成功保存的时刻，静置不闪不转；② 正在保存——16px 转圈小指示＋「正在保存…」，只在保存进行时出现，存好即换成已保存，不许一直转；③ 保存失败——红点＋「保存失败」＋文字按钮「重试」，一次说清出了什么事（网络断了 / 没权限 / 版本冲突），已输入的内容原样留在编辑器里，不许清空、不许悄悄回滚到旧版；④ 草稿未同步——灰点＋「草稿未同步 · 离线」，离线时输入照常、内容只存本地，联网后自动补发、不让用户重发（复用条目 19 口径）
  - 时序纪律：输入停止约 800ms（建议）后自动保存，不许每敲一个字就存一次；保存中再次输入，当前保存完成后立即再存一次，不许丢掉中间改动；保存成功后时间戳更新，不许用「刚刚」这类模糊词
  - 重试纪律：点「重试」只重发失败的那一次保存，不许整篇重传、不许弹确认框；重试中回到「正在保存…」态；连续失败 3 次（建议）后文案改成「保存失败 · 已保留本地草稿」，并给「导出副本」出口
  - 冲突：云端已有更新版本时不许悄悄覆盖——弹「版本冲突」提示，给「保留我的 / 用云端的 / 对比查看」三选，不许自动选、不许默认覆盖
  - 减动效：prefers-reduced-motion 时转圈改静置三点，态间切换只淡入淡出 150ms
- 动效：演示是一块真编辑器——打字后状态格先变「正在保存…」转圈，约 1s 后落定「已保存 · 当前时间」；点「模拟失败」看红点＋重试，点重试看回正在保存再落定；点「断网」开关看草稿未同步态、继续打字不拦人，恢复联网后自动补发、时间戳更新
